# NSData compression

Build nsdata-compression.m against Foundation/CoreFoundation and run it under Darling. It checks `-[NSData compressedDataUsingAlgorithm:error:]` and `-[NSData decompressedDataUsingAlgorithm:error:]` against the public documentation: instances of `NSData`, `NSMutableData` and CoreFoundation's bridged data class respond, LZFSE and Zlib round-trip a short string, 1 MB of repeating bytes (which compresses to fewer bytes) and 256 KB of pseudo-random bytes, garbage and a truncated stream do not decompress and set `*error`, and `error:NULL` is accepted on success and on failure.

Baseline: against the base commit the header has no `NSDataCompressionAlgorithm` and no declaration of either method (an error, then `-Wobjc-method-access` warnings), and the first call raises `unrecognized selector`; candidate: zero failures.

All four algorithms are exercised (LZFSE, LZ4, LZMA and Zlib). nsdata-compression-macos.h holds streams written by macOS 26.7.3 for two inputs (a short text and 140000 bytes in 1 KiB runs, which gives several LZ4 blocks); they must decompress here, and the LZFSE and Zlib streams of the short input must equal the bytes macOS writes. Streams written here for the same inputs were decompressed on macOS 26.7.3 (with NSData and with compression_decode_buffer) and on macOS 10.14.4 (compression_decode_buffer, x86_64 and i386). The methods themselves exist from macOS 10.15 on.

What was observed on macOS 26.7.3: the raw values of the four cases (LZFSE 0, LZ4 1, LZMA 2, Zlib 3); NSCocoaErrorDomain code 5377 for garbage, a truncated stream and an empty input (an empty NSData compresses and decompresses back to empty data); an algorithm value outside the four cases raises NSInvalidArgumentException in both methods; the result is an immutable NSData for every receiver; compressing no bytes with LZ4 gives the 12 byte stream of an empty stored block and the end tag. The one remaining guess is the code 5376 of a compression failure, which cannot be provoked. The refusal of Zlib inputs of 4 GiB or more is not tested: it would need allocations of that size.
